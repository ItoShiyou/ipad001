# 要件定義書 v0.1（レビュー用ドラフト）

製品: 電子楽譜リーダー（コードネーム未定）
状態: **ドラフト。§11 の確認事項に回答を得てから v1.0 として確定する**
前提: [`decision.md`](decision.md)

---

## 1. 製品定義

> **本番で絶対に落ちない譜面台。**

演奏者が自分の PDF / 画像の楽譜を持ち込み、iPad を譜面台として使うためのアプリ。
通信しない。アカウントを作らせない。機能数で競わず、**演奏中に一切詰まらないこと**に集中する。

### 設計原則（迷ったらここに戻る）

| # | 原則 | 帰結 |
|---|---|---|
| P1 | **演奏中の1フレームは、どんな機能よりも重い** | 演奏モード中は一切のバックグラウンド処理を止める |
| P2 | **通信しないことは制約ではなく機能** | ネットワーク権限を持たない。プライバシーラベルは "Data Not Collected" |
| P3 | **ユーザーの楽譜を壊さない** | 元PDFは非破壊。注釈は別レイヤ。上書き保存を既定にしない |
| P4 | **買い切りで売った機能を後から取り上げない** | サブスクへの機能移動を将来にわたって行わない |
| P5 | **本番で使う操作は、暗所で・見ずに・片手で行える** | 譜めくりとセットリスト移動が最優先。設定は演奏中の導線に置かない |
| P6 | **自動化された仕組みは「提案」しかできない。人間の操作が常に勝つ** | カメラ・自動スクロールは、いつでも手動入力に即座に上書きされる。既定は無効 |

|---|---|---|---|
| UC1 | **本番演奏** | 譜めくりが確実。落ちない。暗いステージで見える。誤操作しない | **最高** |

### 3.7b ハンズフリー譜めくり

**背景**: 両手が塞がる奏者（ギター、鍵盤、弦楽器）にとって、フットスイッチの購入は導入障壁になる。
追加購入なしに、暗いステージで確実にめくれる手段が要る。

> ⚠️ **方式は未決定。** 候補の全体像・評価・着手順は
> **[`page-turn-input.md`](page-turn-input.md) に分離して保持する。**
> カメラ（顔）は候補のひとつにすぎず、**より確実な手段（MIDIペダルボード、iPhoneをローカル直結
> リモートにする方式）を先に実装する。** 下記 FR-80 以降は「カメラ方式を採用する場合の要件」であり、
> スパイク SP-2〜SP-5（§12）の結果を見てから採否を決める。
>
> 入力層は**複数方式を同時に有効化でき、どれが来ても同じ譜めくりイベントになる**構造にする。
> これにより方式の採否を後から差し替えても製品の中核が揺れない。

**本節は、この製品の約束（本番で落ちない）を最も壊しやすい機能である。**
以下の安全設計を満たせない限りリリースしない。

| ID | 要件 | 優先 |
|---|---|---|
| FR-80 | 前面カメラの顔検出により、**片目のウインク**で譜めくりできる（左=戻る / 右=進む、割り当て変更可） | S |
| FR-81 | **両目の同時まばたきは無視する**（自然なまばたきで誤動作しないため） | **M（FR-80採用時）** |
| FR-82 | ウインクは**一定時間（既定400ms、250〜1000msで調整可）保持**して初めて成立する | **M（同上）** |
| FR-83 | 1回めくった後は**クールダウン（既定1.5秒）**を置き、連続誤発火を防ぐ | **M（同上）** |
| FR-84 | 代替ジェスチャとして**首を傾ける / うなずく**を選べる | C |
| FR-85 | **キャリブレーション画面**を持つ。実際のステージ照明下で検出状況・信頼度を確認し、閾値を調整できる | **M（同上）** |
| FR-86 | 検出が有効なとき、演奏ビューに**小さな常時インジケータ**を出す（今どちらの入力が生きているか常に分かる） | **M（同上）** |
| FR-87 | 顔を一定時間見失ったら**自動的に無効化**し、その旨を表示する（暗転・移動中の誤発火を防ぐ） | **M（同上）** |
| FR-88 | TrueDepth 搭載機では **ARKit（赤外線）** を使い、非搭載機では **Vision（可視光）** にフォールバックする。どちらで動作しているかをキャリブレーション画面に明示する | S |
| FR-89 | カメラ映像は**一切保存せず、端末外にも出さない**。アプリはネットワーク権限を持たないため物理的に送信できない旨を、権限要求時に明示する | **M（同上）** |

**暗所の扱い**: TrueDepth は赤外線のため**暗闇でも動作する**が、Vision（可視光）は
ステージ照明下で著しく劣化する。したがって非搭載機では「暗所では使えない可能性がある」と
キャリブレーション時に正直に警告し、**フットスイッチ / MIDI を第一の手段として案内する。**

### 3.7c 演奏タイミングの記録と自動スクロール

**背景**: 一度通して演奏し、そのときの譜めくりタイミングを記録しておけば、
次回以降は自動で進められる。音響追従（音を聴いて楽譜位置を推定する）は ML と DSP の重い実装だが、
**「人間が一度お手本を示す」方式なら、それを回避して実用価値の8割を取れる。**

| ID | 要件 | 優先 |
|---|---|---|
| FR-90 | 演奏中の譜めくり操作を、曲の開始からの経過時間とともに**記録**できる（テイクと呼ぶ） | S |
| FR-91 | 1曲に**複数テイク**を保持し、名前を付けて選べる（「リハ本番用」「テンポ遅め」など） | S |
| FR-92 | 記録したテイクを再生し、**自動で譜めくり**する | S |
| FR-93 | 再生方式を選べる: **(a) 記録時刻でページを送る / (b) マーク間を補間して連続スクロール** | S |
| FR-94 | **時間基準と拍基準を選べる。** 曲にテンポが設定されている場合は拍で記録し、テンポを変えても**ずれない** | S |
| FR-95 | 演奏中に**テンポ倍率**（0.8〜1.25倍程度）を変更でき、残りのタイムラインが追従する | S |
| FR-96 | 演奏中に**ナッジ**（前後に数秒ずらす）ができ、残りのタイムライン全体が平行移動する | **M（FR-92採用時）** |
| FR-97 | **手動操作は常に自動より優先する。** タップ・ペダル・MIDIの入力があった瞬間、その位置に自動再生が同期し直す（自動が人間を上書きしない） | **M（同上）** |
| FR-98 | 「次のめくりまであと N 秒」を細い進捗表示で予告する（奏者が身構えられること自体が信頼につながる） | **M（同上）** |
| FR-99 | 自動再生は**曲単位でオプトイン**。既定は無効。**自動で前ページに戻ることは決してしない** | **M（同上）** |

**適用範囲を正直に**: この機能が有効なのは**アレンジが固定された、繰り返し演奏する曲**である。
自由なテンポで解釈するクラシック独奏や、即興の比重が大きい演奏には向かない。
ストア説明でもその前提を明記し、期待値を裏切らない。

## 4. 非機能要件 ★ここが製品そのもの

宣伝文句が「本番で落ちない」である以上、以下は**機能ではなく設計制約**として扱い、CIで計測する。

| ID | 要件 | 目標値 | 測定方法 |
|---|---|---|---|
| NFR-01 | **譜めくりの応答** | 操作から描画完了まで **16ms 以内**（1フレーム）。事前描画済みページのみ表示 | Instruments、実機 |
| NFR-02 | **起動から譜面表示まで** | コールドスタート **2.0秒以内**（最後に開いていた曲を復元） | 実機計測 |
| NFR-03 | **メモリ上限** | 保持は「現在・前・次」の3ページのみ。大判PDFはタイル分割 | ピークメモリ計測 |
| NFR-04 | **クラッシュ率** | **ゼロを最優先KPI**とする | Xcode Organizer |
| NFR-05 | **演奏モード中のバックグラウンド処理** | **全面停止**。サムネイル生成・インデックス作成・ファイル走査は演奏外のみ | コードレビュー＋計測 |
| NFR-06 | **自動スリープ** | 演奏モード中は抑止。電池低下時の挙動を明示 | — |
| NFR-07 | **オフライン動作** | ネットワーク権限を持たない。機内モードで全機能が動く | 手動テスト |
| NFR-08 | **データ喪失耐性** | 強制終了・電池切れでも注釈とセットリストを失わない | 異常終了テスト |
| NFR-09 | **アクセシビリティ** | VoiceOver、Dynamic Type、コントラスト | — |
| NFR-10 | **カメラ検出の処理予算** | 顔検出は**縮小フレーム・15fps以下**で回し、1フレーム **5ms 以内**。譜めくり描画スレッドを妨げない | Instruments |
| NFR-11 | **カメラ使用時の電池** | 2時間の連続使用で**残量30%以上を維持**（満充電開始、輝度50%） | 実機での連続稼働試験 |
| NFR-12 | **誤発火率** | 30分の通常演奏（カメラ有効・意図的なウインクなし）で**誤めくり0回** | 実機シナリオ試験 |

## 6. データモデル（概略）

```
Library
├── Score（曲）
│   ├── title, composer, ensemble, tags, createdAt
│   ├── PageSource[]        … PDF/画像の実体への参照 + ページ範囲
│   ├── PageSetting[]       … ページごとの crop / 回転
│   ├── AnnotationLayer[]   … PencilKit の描画データ（ページ単位、元PDFとは別）
│   ├── JumpPoint[]         … リピート / D.S. / Coda のジャンプ先
│   └── PracticeSetting     … テンポ、拍子、最後の表示位置
└── Setlist
    ├── name, createdAt
    └── SetlistItem[]       … Score参照 + 曲ごとのメモ + 並び順
```

永続化は SwiftData。PDF実体はアプリコンテナ内に保管し、DBには参照のみ持つ。

## 7. 画面構成（概略）

1. **ライブラリ** — 曲一覧、検索、タグ絞り込み、取り込み
2. **セットリスト一覧 / 編集**
3. **演奏ビュー** ★中核 — 譜面全画面。UIは最小限。譜めくり・曲移動・注釈トグルのみ
4. **曲の詳細・設定** — メタデータ、トリミング、ジャンプ先登録
5. **設定** — 表示、ペダルの割り当て、バックアップ、購入

## 8. v1.0 で作らないもの（明示的に捨てる）

クラウド同期 / 楽譜の共有・配信 / コミュニティ / 楽譜販売 / OMR（楽譜画像の音符認識） /
音響追従の自動譜めくり / アカウント登録 / MIDI連携 / 録音。

**理由: いずれも「落ちない」という約束を薄める。** ただし §11-Q7 の回答次第で
**アンサンブルの複数台同期**のみ再検討する（サーバーなしのローカル直結で実現可能なため）。

## 9. 受け入れ基準（本番シナリオ）

v1.0 は以下を実機で通してからリリースする。

| # | シナリオ | 合格条件 |
|---|---|---|
| AT-1 | 30曲・計400ページのライブラリで、セットリスト12曲を通しで演奏 | 全譜めくりが1フレーム以内。クラッシュ・詰まりゼロ |
| AT-2 | 機内モードで全機能を実行 | 全機能が動作。購入状態も保持 |
| AT-3 | 演奏中に電池切れ→再起動 | 注釈・セットリスト・表示位置が失われない |

| AT-7 | 演奏中に他アプリから通知・電話着信 | 譜面表示が崩れず、復帰後も位置を保つ |

| **Piascore の評価が実は高い**（未確認） | 参入余地の前提が崩れる | §11 の前に `appstore_probe.py` で確認（2分） |
| ¥500（Piascore）の価格アンカー | ¥2,500 が高く見える | 無料3曲で品質を体験させてから提示。§11-Q13 で要検証 |
| 大判PDFの描画性能 | NFR-01 未達 | タイル分割と事前描画。早期にプロトタイプで検証 |
| ペダル機種ごとの挙動差 | 一部で動かない | 主要機種のキーコードを設定で再割り当て可能にする |
| **forScore が顔ジェスチャーを既に実装済みの可能性** | 差別化にならない | **要検証（§11-Q15）。** 「あるが不安定」なら、暗所耐性と誤発火ゼロで勝ちに行く |
| **カメラ検出がステージ照明で機能しない** | 目玉機能が本番で使えない | TrueDepth（赤外線）機を主対象に。可視光機では正直に警告し、MIDI/ペダルを第一手段として案内 |
| **カメラ常時稼働が NFR-01 / NFR-05 と衝突** | 譜めくりが遅くなる | **P1 でスパイクして計測してから採否を決める**（§12） |

## 12. 先行検証（スパイク）— 実装の最初にやること

新規機能は魅力的だが、**性能の前提が崩れたら製品が成立しない。**
機能を作り込む前に、以下を実機で測って採否を決める。

| # | 検証すること | 判定基準 | 不合格なら |
|---|---|---|---|
| SP-1 | **PDF事前描画パイプライン** — 大判PDFでの譜めくり応答 | NFR-01（16ms） | 全体設計の見直し。**最優先** |
| SP-2 | **顔検出を回しながらの譜めくり** — カメラ稼働時の描画への影響 | NFR-01 と NFR-10 を同時に満たす | カメラ機能を v2 送り |
| SP-3 | **暗所での顔検出** — TrueDepth機 / 非TrueDepth機の両方、ステージ照明を模した条件 | 実用可能な検出率 | 非TrueDepth機では機能を提供しない |
| SP-4 | **誤発火試験** — 30分の通常演奏でウインクなし | NFR-12（誤めくり0回） | 閾値再設計、または不採用 |
| SP-5 | **電池** — カメラ有効で2時間連続 | NFR-11 | 既定オフ＋警告表示 |
| SP-6 | **MIDI入力** — 主要なギター用マルチエフェクターからの Program Change 受信 | 遅延20ms以内、取りこぼしなし | — |

**SP-1 と SP-6 は v1 の必須要素。SP-2〜SP-5 の結果次第でカメラ機能の v1 採否を決める。**
