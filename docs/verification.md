# 検証ラウンド2 — 別アプローチによる再調査と、初回調査の訂正

実施日: 2026-09-03 / 手法: 独立した3系統の並行調査（軽量モデル）＋ ヘッドレスブラウザ経路の実測

初回調査（`research.md` / `monetization.md`）の結論を、**別のアプローチで再現できるか**を検証した。
結果は **不一致**。初回の結論は採用できない。

---

## 0. ブラウザ経路の実測結果 — 使えない

「Chrome を使えば App Store を直接見られるのでは」という仮説を、Chromium (Playwright) で実測した。

| 対象 | 結果 |
|---|---|
| `apps.apple.com` | `ERR_TUNNEL_CONNECTION_FAILED` |
| `itunes.apple.com` | `ERR_TUNNEL_CONNECTION_FAILED` |
| `play.google.com` | `ERR_TUNNEL_CONNECTION_FAILED` |
| `duckduckgo.com` | `ERR_TUNNEL_CONNECTION_FAILED` |

ブロックは HTTP レスポンスではなく **CONNECT トンネルの段階**で発生しており、検索エンジンすら通らない。
この環境の egress は許可リスト方式であり、**ブラウザを立てても迂回にはならない**（組織のポリシー拒否のため迂回は試みない）。

→ **一次データの取得は、制限のない環境でしか行えない。** `tools/appstore_probe.py` の存在理由。

## 1. 最重要の発見 — 「評価3.5」という条件は、有名アプリを指さない

初回調査で私は「買い切りアプリの後出しサブスク化 → 評価3.5に低迷」という筋書きで候補を選んだ。
**この筋書きは誤りだった。**

| アプリ | 炎上の事実 | 現在の評価（二次情報） |
|---|---|---|
| Ulysses | 2017年サブスク化で 2.5 まで急落 | **約4.5に回復** |
| Fantastical | サブスク化で 2.8 まで急落 | **約4.7に回復** |
| Notability | 2021年サブスク化で大炎上・返金騒動 | 回復済み |
| GoodNotes 6 | UI改悪で現在進行形の炎上 | **約4.8 / 12.8万件** |
| GoodReader | 「買い切りなのに年額課金を要求」の不満は実在 | **約4.66 / 約14,000件**（JP 約4.5 / 約5,700件） |
| Teleprompter Pro | 年$95課金・解約後請求などの不満は実在 | **約4.75 / 15万件超** |
| PromptSmart Pro | $29買い切り＋追加課金、クラッシュ報告 | **約4.61 / 約12,000件** |
| Anytune | — | **約4.8 / 8,207件** |
| Capo | beat detection 精度への不満は実在 | **約4.7** |

**構造的な理由**: レビュー総数が数万〜十数万件ある大型アプリでは、炎上時の低評価は
**過去の高評価に希釈され、集計値は4.5〜4.8に戻る**。「炎上した」と「評価が3.5」は別物である。

> **したがって「評価3.5前後」で実際に低迷しているのは、炎上から回復する体力（ユーザーベースと
> 開発リソース）を持たない、小規模で放置気味のニッチアプリの方である。**
> 依頼者の選定基準は、有名アプリではなくこちらを指している。

### 収益試算への影響

`monetization.md` の**単位経済と固定費（損益分岐点＝年7本）は維持できる**。手数料15%が
有料アプリに適用されることが確認できたため。

一方、**販売本数シナリオ（悲観20本／標準100本／好調400本）の妥当性検証は無効**である。
検証に使った有料アプリCVRに出典がなく、業界にも公開データが存在しないため。
**この3シナリオは「もしこれだけ売れたら」という感度分析としてのみ読むこと。**
「標準シナリオが妥当」という初回の主張は撤回する。

## 4. 白紙調査（初回の結論を伝えずに実施）の結果

同じ6条件からゼロベースで候補を洗い出させた。**初回の上位3候補（音楽練習プレイヤー、
スポーツ動作分析、テレプロンプター）はいずれも再現されなかった。**

さらに、この白紙調査は2回の実行で**互いに異なる候補群**を出しており（1回目: オフライン地図／
手書きノート、2回目: INKredible／電子楽譜）、**それ自体が「この環境では候補選定が安定しない」
ことの証拠**である。

数値の裏付けを伴って挙がった唯一の候補:

| 候補 | 評価 | 内容 |
|---|---|---|
| **INKredible / INKredible PRO**（手書きノート） | **Google Play 3.34 / 約25,000件**（PRO版 3.94 / 約1,500件）。iOS版は不明 | 「20文字ごとに固まる」「指で触れないとペン入力を受け付けない」等の**入力の根幹のバグ**。個人開発規模で放置気味 |
| **Piascore**（電子楽譜リーダー、日本） | 星評価は**未取得** | 「本番中にフリーズして完全応答不能」「メトロノームとチューナーが同時使用不可」「Dropboxから開くと既存楽譜が上書きされる」。基本無料＋¥500の買い切りアップグレード |

## 5. 結論

**初回調査の結論は再現されなかった。実装には進まない。**

確度をもって言えることは3点のみ:

1. **選定基準の向き先が間違っていた。** 「評価3.5」は有名アプリの炎上ではなく、
   **小規模で放置気味のアプリ**を指す。初回に挙げた競合は全て4.5以上だった。
2. **単位経済（15%手数料、年約1.7万円の固定費、損益分岐点7本）は有効。**
   サーバーを持たない方針の優位は揺らいでいない。
3. **販売本数の予測は、現時点では誰にもできない。** 有料アプリのCVRに公開データがない。

**次にやるべきことは、候補を増やすことではなく、一次データを取ることである。**
`tools/appstore_probe.py` を制限のない環境で実行し、`averageUserRating` と
`userRatingCount` で 3.2〜3.8 のレンジに入るアプリだけを残してから再ランキングする。
